Aspected vs plain vector search

Same question. Two rankings.

Questions people ask

Isn't Aspected a vector database too?

Yes. The difference is what goes into the vector. A plain vector search embeds the text, so meaning is all it sees. Aspected builds the vector from aspects, such as meaning, version, date, source or price, each with its own weight, and ranks on all of them in one calculation.

Isn't that just a filter?

A filter says yes or no and drops everything else, including the almost-right. An aspect says how close a record is, so a near match still ranks, only lower.

How is it different from hybrid search, boosting or a reranker?

Those add rules or a second model on top of one score, and every rule interacts with the others. Aspected ranks on all aspects in the first pass and shows the distance per aspect.

Do I still need a language model?

To write the answer, yes. To decide which documents it reads, no: ranking is a calculation.

Does it replace Copilot or my vector database?

It replaces the retrieval step. Copilot, your chat or your agent stays the screen and reads from Aspected over its REST API.

Who decides what counts?

The people who own the content. They set the weights, or pick the better of two results and the weights follow.

Can I see why a document was used?

Yes. Every answer comes with a receipt: what was used, what was kept out and which aspect decided. It shows why a document was selected, not that the answer is right.

Where does my data live?

In your own AWS account, including the European Sovereign Cloud. Smaller catalogues can run hosted by us.

Instructions for your AI

Copy this into Claude Code, Claude, or another AI assistant with a terminal.

You are helping me try Aspected, a database that ranks records on several weighted aspects at once and shows the distance per aspect.

1. Read https://docs.aspected.com first, starting with Getting Started and the Tutorial. Follow it for installing, the license key and the REST API. Do not guess commands that are not in the docs.
2. Pull and run the Docker image from the docs (xillio/aspected, port 8080). Check that http://localhost:8080/indexes responds.
3. Ask me for a dataset: a CSV, an Excel file or a folder of documents. If I have none, use a small public CSV.
4. Profile the data and propose a schema: one aspect per useful column, each with a resolver from the docs (enum, text, number or datetime). Show me the list and wait for my OK.
5. Create the index, train it with my data and run three "like this, but" searches, for example "like this one, but cheaper". For each result, show the distance per aspect.
6. Change one weight, run the same query again, and show me what moved and why.
7. End with a short summary: what you built, the commands you ran, and how my own apps can call it over the REST API.

Rules: ask before installing anything new, keep my data on this machine, and stop and ask me when the docs and my setup disagree.

Get your data ready

Aspected works with the data you have. These six checks make the first results better.

  1. One row per thing people look for.A product, a document, a session or a contract. Not one row per sale or per page.
  2. Columns become aspects.Each gets a resolver: text for descriptions, number for price or size, enum for a fixed list such as type or department, datetime for dates.
  3. One unit per column.All grams or all kilos, all euros or all dollars. Mixed units look like outliers.
  4. Empty means unknown.Leave a value empty when you don't know it. A zero is read as a real zero.
  5. Say which version counts.For documents, keep version, status (draft, published, superseded), owner and source. They decide which copy the AI reads.
  6. Keep the copies.Don't clean out near-duplicates first. Aspected finds them and shows what separates them.

Documents on file shares or SharePoint? Xillio's connectors bring them in with their version, date, owner and department.
